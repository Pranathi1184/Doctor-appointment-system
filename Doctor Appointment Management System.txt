Doctor Appointment & Consultation Management System
Software Requirement & Design Document

---

1. Project Overview

The Doctor Appointment & Consultation Management System is a web-based application that enables patients to register, search for doctors, book appointments, and receive consultation details and prescriptions online.

The system simplifies the healthcare consultation process by allowing doctors to record patient diagnosis, provide prescriptions, and recommend follow-up appointments.

The platform supports three user roles:
• Admin
• Doctor
• Patient

The application is built using a MERN stack architecture:
Frontend: React.js
Backend: Node.js (Express.js)
Database: MongoDB

3. System Architecture

The system follows a three-tier architecture:

React Frontend
↓
Node.js REST API (Express)
↓
MongoDB Database

The frontend sends requests to backend APIs, which process data and interact with the database before sending responses back to the user interface.

---

4. User Roles

Admin

Admin manages system data and users.

Admin can:
• Create and manage doctor accounts
• Manage patient users
• View all appointments
• Monitor system activity

---

Doctor

Doctors handle consultations and patient treatment.

Doctors can:
• View assigned appointments
• Add consultation notes (diagnosis and observations)
• Provide prescriptions with medicines and dosage
• Recommend follow-up appointments

---

Patient

Patients use the system to book consultations.

Patients can:
• Register and login
• Search and view doctors
• Book appointments
• View consultation notes
• View prescriptions
• View follow-up recommendations

8. Backend API Design

Base API:
/api

Authentication APIs
POST /api/auth/register → Register user
POST /api/auth/login → Login user

Doctor APIs
GET /api/doctors → Get all doctors
GET /api/doctors/:id → Get doctor details

Appointment APIs
POST /api/appointments → Book appointment
GET /api/appointments/patient → Patient appointments
GET /api/appointments/doctor → Doctor appointments

Consultation Notes APIs
POST /api/notes → Add doctor notes
GET /api/notes/:appointmentId → Get notes

Prescription APIs
POST /api/prescriptions → Add prescription
GET /api/prescriptions/:patientId → Get prescriptions

Follow-Up APIs
POST /api/followup → Add follow-up
GET /api/followup/:patientId → Get follow-ups

11. Business Rules

• Only registered users can book appointments
• Doctors can only manage their own appointments
• Consultation notes must be added after consultation
• Prescriptions must be linked to consultation notes
• Patients can only view their own data
• Follow-up recommendations are optional and doctor-controlled
